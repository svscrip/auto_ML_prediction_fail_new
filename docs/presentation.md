# План демонстрации — Яньшин А.

Учебная доработка группового проекта, ветка `yanshin`.
Полная [речь для защиты](defense.md) подготовлена по уточнениям из первых 15 минут вебинара 6.
Ориентир — 10–12 минут с переключением заранее открытых файлов; лимит в этом
фрагменте вебинара не установлен. Репетиция с таймером нужна отдельно.

1. README: бизнес-задача, происхождение проекта, ссылки на три задания.
2. Poetry и `.venv`: зависимости, lock-файл, воспроизводимость, `.gitignore`.
3. Pre-commit и CI: Black, isort, Flake8, pytest, найденные и исправленные сбои.
4. [Model Card](../model_card.md): 17 признаков, 6 категориальных, источник и метрики.
5. Ограничения: недоступность флагов до отказа, зависимость признаков от пакета,
   early stopping и калибровка. [Отдельное сравнение](feature-ablation.md):
   AUC 0.9537 → 0.9144, ложные тревоги 869 → 2 762 при пороге 0.5.
   Исключение шести признаков не подтверждает доступность остальных до отказа.
   Показать условия пилота в разделе 4 карточки: обе версии пока не допущены.
6. [Бизнес-процесс](../Model_BPMN.md): данные → модель → инженер → действие → измерение эффекта.
7. [Переобучение](../Model_retrain_BPMN.md): PSI датчиков, доля отказов (target drift),
   снижение качества, объём новых данных, расписание и ручной запрос. Далее —
   проверка данных, сравнение моделей, человек, версия, деплой и откат.
8. Итоги: 75 локальных тестов и 90 954 прогноза в проверке коммита `e13ae9e`;
   [полностью успешный CI для e13ae9e](https://github.com/svscrip/auto_ML_prediction_fail_new/actions/runs/40125876517)
   с Python 3.11–3.13 и Docker.
   Эти проверки не заменяют независимую оценку качества раннего предупреждения.

Не использовать старый демонстрационный `artifacts/example_metrics.json` как результат текущей модели.
Не представлять спроектированные внешние интеграции как уже работающие.
